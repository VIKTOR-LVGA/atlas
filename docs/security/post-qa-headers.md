# ATLAS security headers — post-QA decision record

Date: 2026-10-19  
Scope: web responses generated by the Next.js application

## Enforced now

- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy`: camera, microphone, geolocation and browsing-topics disabled
- `X-Frame-Options: DENY`

These headers are emitted for every application path through `next.config.ts`.

## CSP rollout

The initial Content Security Policy is emitted as
`Content-Security-Policy-Report-Only`. It restricts the default, base, form,
frame, object, image, font, worker and manifest sources. Browser connections to
the configured Supabase project are allowed because ATLAS Auth and Realtime use
Supabase directly from the client.

Next.js and the synchronous theme bootstrap currently require inline script or
style support. The policy therefore includes `unsafe-inline` while violations
are reviewed. This is not presented as the final CSP posture.

Before enforcement:

- [ ] collect CSP violations on an authenticated Preview deployment;
- [ ] exercise login, password recovery, upload, analysis and Realtime;
- [ ] replace inline allowances with nonces or hashes where practical;
- [ ] narrow `connect-src` to the exact Supabase project hosts;
- [ ] add a reporting endpoint (`report-to` or `report-uri`) with an approved
      data-retention policy;
- [ ] enforce the resulting policy and repeat the full browser suite.

## CORS observation

The audit observed `Access-Control-Allow-Origin: *` on public Vercel HTML. The
repository does not configure that response header and this change does not add
it. A wildcard on public HTML is not an authorization control. Sensitive ATLAS
data remains protected by authentication, Supabase Row Level Security and
server-side authorization; credentialed CORS must not be enabled with a
wildcard origin. Platform response headers should be rechecked on Preview and
Production after deployment.

OpenAI requests are server-side and are intentionally not added to browser CSP
or CORS allowlists.
